# LiteLLMModelAlias

An **alias** is a stable, human-chosen name that points at a real LiteLLM
model. `ackstorm.smart` today may resolve to `gemini.gemini-pro-latest` and
tomorrow to something else; callers keep using `ackstorm.smart`. Projected into
`router_settings.model_group_alias` via `POST /config/update`.

## Quick reference

| Field                   | Required | Notes                                                                         |
|-------------------------|----------|-------------------------------------------------------------------------------|
| `spec.aliases[].name`   | yes      | The name clients send to LiteLLM. Cluster-wide unique across ALL alias CRs.    |
| `spec.aliases[].value`  | yes      | The LiteLLM `model_name` (or model group) it resolves to. Forwarded verbatim.  |
| `spec.aliases[].fallbacks` | no    | Models tried in order when the call still fails. See [Fallbacks](#fallbacks).   |

```yaml
apiVersion: litellm.ackstorm.ai/v1alpha1
kind: LiteLLMModelAlias
metadata:
  name: ackstorm-aliases
  namespace: litellm-system
spec:
  aliases:
    - name: ackstorm.smart
      value: gemini.gemini-pro-latest
    - name: ackstorm.fast
      value: gemini.gemini-flash-latest
```

## One map, many CRs

Every `LiteLLMModelAlias` in the cluster is aggregated into a single
`model_group_alias` map, so all CR events coalesce onto one reconcile and
produce ONE write to LiteLLM per debounce window.

Because the map has one slot per name, two CRs declaring the same alias name
conflict. The winner is decided alphabetically-last on
`(namespace, name, array index)`; losers report `Ready=False` with
`reason=AliasConflict` and name the winner in `status.aliasStatuses[]`. See
[Conflict Resolution](../concepts/conflict-resolution.md).

The operator owns the whole map. An alias set in the LiteLLM UI or through
the API, with no CR behind it, is removed on the next reconcile; with no
`LiteLLMModelAlias` in the cluster the map is emptied. Declare every alias you
want to keep as a CR.

`applied: true` on an entry means the operator successfully wrote it into
LiteLLM — **not** that the value resolves to a real model. An alias pointing at
a name LiteLLM does not know is written happily and fails only at call time.

## Fallbacks

```yaml
spec:
  aliases:
    - name: ackstorm.super
      value: gemini.gemini-4-argon
      fallbacks:
        - gemini.gemini-4-carbon
        - anthropic.claude-sonnet-5
```

The operator writes `{"ackstorm.super": [...]}` into
`router_settings.fallbacks` in the same `POST /config/update` as the alias.
Names are forwarded verbatim, like `value`; a fallback may itself be an alias.
Everything else is LiteLLM's behaviour:

- **When it fires.** After the retries on the primary are exhausted
  (`router_settings.num_retries`), on any error not covered by its
  context-window or content-policy fallbacks. A stream falls back only if it
  fails before the first chunk.
- **Slow answers.** Set `timeout` (and `stream_timeout`) on the primary
  `LiteLLMModel`'s `spec.params`. It is per attempt, not a total deadline.
- **Going back.** Nothing is sticky: every request tries the primary first. A
  deployment that keeps failing is skipped while in cooldown
  (`router_settings.cooldown_time`, default 5s). A flapping primary therefore
  alternates models inside one conversation, and each switch misses the
  provider's prompt cache; a longer `cooldown_time` trades that for staying on
  the fallback longer.
- **Only through the alias.** LiteLLM matches the name the client sent, so a
  direct call to `gemini.gemini-4-argon` does not use these fallbacks
  (measured on 1.108.1).

The operator owns the whole `router_settings.fallbacks` list, as it does the
alias map. An entry set in the LiteLLM UI or through the API, whatever its key
(an alias, a real model name, `*`), is removed on the next reconcile; with no
alias declaring fallbacks the list is emptied. Aliases a Discovery generates
carry no fallbacks.

## Generated by a Discovery

A `LiteLLMModelDiscovery` with `spec.aliases` rules writes its own alias CRs
(`<discovery>-aliases-<n>`). They are ordinary alias CRs — same map, same
conflict rules — but owned by the discovery: edit the discovery, not them.
See [Default aliases](model-discovery.md#default-aliases-specaliases).
